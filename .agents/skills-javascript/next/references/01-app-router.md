# App Router

File conventions for the `app/` directory (App Router). A route exists when a folder contains a `page` or `route` file; layouts wrap their child segments and persist across navigations.

## File conventions

| File | Purpose |
|---|---|
| `layout.tsx` | Shared UI (nav, footer). **Root layout** (`app/layout.tsx`) is required and must contain `<html>`/`<body>`. |
| `page.tsx` | Renders the route. Must export a default component. |
| `template.tsx` | Like `layout`, but re-mounts on every navigation (no state sharing). |
| `loading.tsx` | Suspense fallback for the segment; streamed while child data loads. |
| `error.tsx` | Client-side error boundary for the segment; must be a Client Component (`'use client'`) and accepts `error` and `reset` props. |
| `not-found.tsx` | Custom 404 UI; pair with `notFound()`. |
| `global-error.tsx` | Catches errors in the root layout itself (no `reset`). |
| `route.ts` | Route Handler (API endpoint) — see 05-route-handlers-middleware. |
| `default.tsx` | Fallback for a parallel-route slot with no matching page. |

Extensions: `page`/`layout`/`loading`/`error`/`template`/`default` take `.js`/`.jsx`/`.tsx`; `route` takes `.js`/`.ts` (no JSX).

## Structure rules

- Folders are URL segments; nesting folders nests URLs. `app/blog/authors/page.tsx` → `/blog/authors`.
- **Route groups** `(group)/` organize code without affecting the URL: `app/(marketing)/page.tsx` → `/`. Use them to share distinct layouts per section.
- **Private folders** `_name/` are never routed — a safe home for colocated components/utils: `app/blog/_components/Post.tsx`.
- Both `app/` and `pages/` can coexist; the App Router takes precedence for overlapping routes.
- Optional `src/` folder: put `app/`, `pages/`, `public/` inside it and move `middleware.ts`/`instrumentation.ts` there too.

## Dynamic segments

| Folder | Matches | `params` type |
|---|---|---|
| `app/blog/[slug]` | `/blog/a` | `{ slug: string }` |
| `app/shop/[...slug]` | `/shop/a`, `/shop/a/b` | `{ slug: string[] }` |
| `app/docs/[[...slug]]` | `/docs`, `/docs/a/b` | `{ slug?: string[] }` |

- `params` is a **Promise**. `const { slug } = await params` in Server Components; `use(params)` (React) in Client Component pages; `useParams()` hook anywhere in a client tree.
- Sync `params` access still works in 15 but is deprecated — do not write it in new code.
- Type routes with generated helpers: `PageProps<'/blog/[slug]'>`, `LayoutProps<'/blog/[slug]'>`, `RouteContext<'/blog/[slug]'>` (generated by `next dev`, `next build`, or `next typegen`).
- Validate narrow params at runtime (e.g. locale) and call `notFound()` on invalid input rather than widening types.

### `generateStaticParams`

Statically generate dynamic routes at build time. Returns an array of param objects, one per route. Child segments receive the parent's params via `options.params` and run once per parent combination.

```ts
export async function generateStaticParams() {
  const posts = await fetch('https://.../posts').then((r) => r.json())
  return posts.map((post) => ({ slug: post.slug }))
}
```

- With `fetch` inside, requests are deduplicated across the tree.
- `export const dynamicParams` controls unlisted paths (default `true` = render on demand; `false` = 404, so only generated paths exist). This replaces the Pages Router's `fallback`.
- Return an empty array + `dynamic = 'force-static'` to statically render *all* paths at first visit.

## Parallel and intercepting routes

- **Parallel routes**: `app/@modal/...` named slots, rendered via `React.use()` on the slot promise from a parent layout. Every slot needs a `default.js` fallback (build fails without it).
- **Intercepting routes**: render one route inside another's layout (modals/overlays) without changing the URL.
  - `(.)folder` — intercept same level
  - `(..)folder` — intercept parent
  - `(...)folder` — intercept from root (any route)

## Navigation

- `<Link href="/path">` — prefetches by default. `prefetch={false}` disables; `prefetch={null}` disables for dynamic pages only. `replace` swaps history instead of pushing. (`shallow` does not exist in the App Router.)
- Client hooks (`next/navigation`): `useRouter()`, `usePathname()`, `useParams()`, `useSearchParams()` (read-only `URLSearchParams`, **wrap in `<Suspense>`** in static routes), `redirect()`, `notFound()`, `forbidden()`, `unauthorized()`.
- Native history works: `window.history.pushState(...)` then `useRouter().refresh()` to trigger a Next.js data refresh; `replaceState` + `router.refresh()` for in-place updates.
- Route Props helpers: `PageProps`, `LayoutProps`, `RouteContext` — see dynamic segments above.
- The client-side **Router Cache** reuses layout and loading segments across navigations but not page segments (15 behavior; `experimental.staleTimes` can re-enable page reuse).
