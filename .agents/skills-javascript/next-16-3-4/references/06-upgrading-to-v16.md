# Upgrading to Next.js 16

Source of truth for migrating an app from Next.js 15 to 16. The official upgrade guide ships in-repo at `node_modules/next/dist/docs/` on 16.2+.

## Requirements

| | |
|---|---|
| Node.js | **20.9+** (18 unsupported) |
| TypeScript | 5.1+ |
| Browsers | Chrome/Edge/Firefox 111+, Safari 16.4+ |
| React | App Router uses React canary (19.2 features: View Transitions, `useEffectEvent`, `Activity`) |

## Steps

1. Point agent docs at the version-matched docs (optional but recommended): `npx @next/codemod@canary agents-md` — writes an `AGENTS.md` block telling agents to read `node_modules/next/dist/docs/` before coding.
2. Run the upgrade codemod (mechanical changes only):
   ```bash
   npx @next/codemod@canary upgrade latest
   ```
   It updates `next.config` for the new `turbopack` key, migrates `next lint` → ESLint CLI, migrates `middleware` → `proxy` (files, function name, `skipMiddlewareUrlNormalize` → `skipProxyUrlNormalize`), strips `unstable_` prefixes from stabilized APIs, removes `experimental_ppr` segment config.
   If the app still uses **synchronous** `params`/`searchParams`/`cookies()`/`headers()`/`draftMode()` from the v15 compat period, also run:
   ```bash
   npx @next/codemod@canary next-async-request-api .
   ```
3. Or install manually: `npm i next@latest react@latest react-dom@latest` (+ `@types/react`, `@types/react-dom` for TS).
4. Work through the breaking changes below; run `next build` and fix.

## Breaking changes

### Turbopack by default

- `next dev` and `next build` use Turbopack without flags. Drop `--turbopack` from scripts.
- **A custom `webpack` config makes `next build` fail** (deliberately). Fix: `--turbopack` to ignore it, migrate the config, or `next build --webpack`. Often a *plugin* injects the webpack option, not you.
- Config: `experimental.turbopack` → top-level `turbopack`. New: `resolveAlias` (webpack `resolve.fallback` replacement, e.g. `fs: { browser: './empty.ts' }`), `debugIds`, advanced loader conditions.
- **Sass tilde imports are gone** — `@import '~bootstrap/...'` → `@import 'bootstrap/...'` (or alias `~*` → `*`).
- Filesystem caching on by default for dev and build.

### Async Request APIs (sync access removed)

These are promises now — `await` (or `use()`): `cookies()`, `headers()`, `draftMode()`, `params` (layout/page/route/default/og-image/icons), `searchParams` (page).

```tsx
export default async function Page({ params, searchParams }: PageProps<'/blog/[slug]'>) {
  const { slug } = await params
  const query = await searchParams
}
```

`npx next typegen` generates the global `PageProps` / `LayoutProps` / `RouteContext` helpers for fully typed migration (no import needed; generated by `next dev`/`next build`/`next typegen`).

### Async image/sitemap ids

`opengraph-image`, `twitter-image`, `icon`, `apple-icon`: the image generator receives `params` and `id` as **Promises** (`generateImageMetadata` still gets sync params). `sitemap`'s `id` from `generateSitemaps()` is a Promise.

### Caching APIs

- **`revalidateTag(tag)` now requires a second argument** — a `cacheLife` profile: `revalidateTag('posts', 'max')`. Single-arg form is a TS error.
- **`updateTag`** (new): Server-Actions-only, immediate expiry + refresh — read-your-writes for forms/settings.
- **`refresh`** (new): refresh the client router from a Server Action.
- **`cacheLife` / `cacheTag`** are stable — drop the `unstable_` import aliases.

### `middleware` → `proxy`

- File: `middleware.ts` → `proxy.ts` (root or `src/`). Named export `middleware` → `proxy` (default export still works, but rename the function).
- **`proxy` runtime is `nodejs` only — `edge` is NOT supported in proxy.** Edge-dependent code must stay on `middleware.ts` (deprecated, to be followed up in a minor release).
- Config renames: `skipMiddlewareUrlNormalize` → `skipProxyUrlNormalize`; new `proxyClientMaxBodySize`.

### `next/image`

- Local image `src` **with query strings** now requires `images.localPatterns` with a `search` pattern (anti-enumeration).
- `images.minimumCacheTTL` default 60s → **4h** (14400).
- `16` removed from default `images.imageSizes`.
- `images.qualities` default → `[75]` only; unknown `quality` prop coerced to nearest.
- Local IP optimization blocked by default (`images.dangerouslyAllowLocalIP` to re-enable; VPC split-horizon DNS 400s).
- `images.maximumRedirects` default unlimited → **3**.
- `next/legacy/image` deprecated; `images.domains` deprecated (use `remotePatterns`).

### PPR → Cache Components

- `experimental_ppr` and all PPR experimental options **removed**. Opt in via top-level **`cacheComponents: true`**. v16 PPR works differently from 15 canaries — if you ran 15 canary PPR, stay on 15 canary and follow the "Migrating to Cache Components" guide.
- `experimental.dynamicIO` and `experimental.useCache` removed (→ `cacheComponents`).

### Routing and navigation

Overhauled prefetching/caching: layout deduplication (shared layout downloaded once for multiple prefetched URLs) and **incremental prefetching** (only uncached parts transferred). No code changes needed; expect *more, smaller* prefetch requests.

### Parallel routes require `default.tsx`

**Every** `@slot` now needs an explicit `default.tsx` — builds fail without one. Keep old behavior with `notFound()` or `return null`.

### Linting

- **`next lint` removed** — run ESLint or Biome directly; `next build` no longer lints. Codemod: `npx @next/codemod@canary next-lint-to-eslint-cli .`
- `eslint` config option removed from `next.config`.
- `@next/eslint-plugin-next` defaults to ESLint **flat config** (`eslint.config.mjs`); migrate legacy `.eslintrc` if needed.

### Scroll behavior

Next 16 **no longer overrides `scroll-behavior: smooth`** during SPA transitions (previously it forced `auto`, navigated, restored). To get the old override back, add `data-scroll-behavior="smooth"` to `<html>`.

### Concurrent `dev` and `build`

`next dev` outputs to `.next/dev`; dev and build can run simultaneously; lockfiles block duplicate `dev`/`build`. Turbopack tracing command is now `npx next internal trace .next-profiles/trace-turbopack.bin`.

### Performance notes

- `next build` output **drops `size` and `First Load JS`** metrics (deemed inaccurate for RSC) — measure with Lighthouse/Real User Monitoring.
- Config is loaded once during `next dev`, so **`process.argv.includes('dev')` is false in your config file** — use `NODE_ENV` or the `phase` argument.

### Removed features

| Removed | Replacement |
|---|---|
| AMP (`amp` config, `useAmp`, `config = { amp: true }`) | None — modern standards |
| `next lint` | ESLint/Biome CLI |
| `serverRuntimeConfig` / `publicRuntimeConfig` / `next/config` `getConfig()` | `process.env` (server) + `NEXT_PUBLIC_*` (client) + `connection()` for runtime reads |
| `devIndicators.appIsrStatus`, `buildActivity`, `buildActivityPosition` | Indicator itself remains |
| `experimental.dynamicIO`, `experimental.useCache` | `cacheComponents` |
| `unstable_rootParams` | `next/root-params` |

### New in 16 (non-breaking highlights)

- **React Compiler** stable: `reactCompiler: true` in config + `babel-plugin-react-compiler` devDep (not default; slower compiles).
- **Build Adapters** (alpha in 16.0; `adapterPath` stable top-level in 16.2) for custom deployment platforms.
- **`<Form>`** component (`next/form`) — progressive-enhancement forms with client-side navigation.
- **`connection()`** — mark a boundary as request-time (env reads, random values, sync DB reads).
- Modern Sass API (`sass-loader` 16).
