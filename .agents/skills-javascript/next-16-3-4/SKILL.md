# next 16.3.4

## Overview

This skill covers **Next.js 16.3.4** (App Router; the Pages Router is legacy). Next.js is a React meta-framework using **file-based routing** (App Router) and **React Server Components** as the default rendering model. Server Components render on the server, fetch data directly, and send zero JavaScript for their markup; Client Components (`'use client'`) add state, effects, and browser APIs. Pages prerender to a static shell that streams in dynamic parts via `<Suspense>`.

Core pillars:

- **File conventions** — `layout`, `page`, `loading`, `error`, `template`, `default`, `route` files map directly to URLs; dynamic segments `[param]`, `[...rest]`, `[[...optional]]`.
- **Data** — `fetch`/ORMs in Server Components; `fetch` is *not* cached by default; `React.cache` dedupes per request.
- **Caching, two models** — the previous model (default) uses `fetch` cache options + route segment config exports; **Cache Components** (`cacheComponents: true`) uses the `'use cache'` directive, `cacheLife`/`cacheTag`, and Partial Prerendering.
- **Mutations** — Server Actions (`'use server'`) for forms and single-roundtrip updates; Route Handlers for APIs; **proxy** (renamed from `middleware` in v16) for request interception.
- **Turbopack** — default bundler for both dev and build since 16.

V16 highlights (full list in [06-upgrading-to-v16](references/06-upgrading-to-v16.md)): Turbopack default, sync access to request APIs removed, `middleware` → `proxy`, `revalidateTag` requires a lifetime profile, PPR replaced by `cacheComponents`, `next lint` removed, Node 20.9+ required.

## Usage

### Installation

```bash
npx create-next-app@latest my-app --yes   # TypeScript, Tailwind, ESLint, App Router, AGENTS.md
cd my-app && npm run dev                  # http://localhost:3000
```

Manual: `npm i next@latest react@latest react-dom@latest` plus scripts `next dev` / `next build` / `next start` (no `--turbopack` flag needed anymore). Root of the app must contain `app/layout.tsx` with `<html>`/`<body>` and `app/page.tsx` — the dev server auto-creates a missing root layout.

### Project structure

```
my-app/
├── app/
│   ├── layout.tsx          # required root layout (<html>, <body>)
│   ├── page.tsx            # /
│   ├── (shop)/             # route group — not in URL, gets its own layout
│   │   └── cart/page.tsx   # /cart
│   ├── blog/
│   │   ├── _components/    # private folder — never routable
│   │   ├── loading.tsx     # streams /blog/*
│   │   └── [slug]/
│   │       ├── page.tsx    # /blog/:slug
│   │       └── error.tsx
│   └── api/route.ts        # Route Handler (REST-style)
├── public/                 # static assets, served at /
├── proxy.ts                # request interception (was middleware.ts)
├── instrumentation.ts      # global hooks
├── next.config.ts
└── .env.local
```

### Minimal page with dynamic params (async!)

```tsx
// app/blog/[slug]/page.tsx
export default async function Page({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params
  const post = await getPost(slug)
  return <article><h1>{post.title}</h1>{post.body}</article>
}
```

Type it with the global `PageProps<'/blog/[slug]'>` helper (generated by `next dev`/`next build`/`next typegen`).

### Server vs client

Default is server. Add `'use client'` on the smallest component that needs state, effects, or browser APIs; everything it imports becomes client-side, while `children`/props from server components stay server-rendered. Pass only serializable props across the boundary; stream promises with React's `use()`. Full patterns (context providers, third-party wrappers, `server-only`/`client-only`) in [02-server-client-components](references/02-server-client-components.md).

### Data and caching

```tsx
// previous model (default) — cache a fetch
const data = await fetch(url, { next: { revalidate: 360, tags: ['posts'] } })

// Cache Components model (cacheComponents: true)
export async function getPosts() {
  'use cache'
  cacheLife('hours')
  cacheTag('posts')
  return db.query('SELECT * FROM posts')
}

// after a mutation (Server Action / Route Handler)
revalidateTag('posts', 'max')   // v16 — profile argument required
updateTag('posts')              // Server Actions only — read-your-writes
```

Streaming slow data: `loading.tsx` (whole segment) or `<Suspense>` (fine-grained; required around uncached/runtime data with Cache Components). Details in [03-data-fetching-and-caching](references/03-data-fetching-and-caching.md).

### Mutations and APIs

```ts
// Server Action
export async function createPost(formData: FormData) {
  'use server'
  // verify auth HERE — actions are reachable via direct POST
  await db.insert(...)
  redirect('/blog')
}

// Route Handler
export async function GET(request: Request) {
  return Response.json({ ok: true })
}

// proxy.ts (was middleware.ts) — nodejs runtime only
export function proxy(request: NextRequest) {
  return NextResponse.redirect(new URL('/home', request.url))
}
export const config = { matcher: '/about/:path*' }
```

See [04-server-actions-and-route-handlers](references/04-server-actions-and-route-handlers.md).

`next.config.ts`: top-level `turbopack` (not `experimental.turbopack`), `images` (defaults tightened in 16), `cacheComponents`, `reactCompiler`, `serverActions`, `headers/redirects/rewrites`. CLI: `next dev|build|start|info|telemetry|typegen|upgrade`. Options in [05-config-and-cli](references/05-config-and-cli.md).

## Gotchas

- **Everything request-related is async in 16** — `params`, `searchParams`, `cookies()`, `headers()`, `draftMode()` are Promises; sync access was removed (it was only a v15 compat shim). `await` them in server code, `use()` them in client pages.
- **`fetch` is not cached by default** — a "static" page that fetches without options re-fetches per request (or blocks). Add `{ cache: 'force-cache' }` / `next: { revalidate }` in the previous model, or `'use cache'` + `cacheLife` in the Cache Components model.
- **`revalidateTag` needs a second argument in 16** — a `cacheLife` profile (`revalidateTag('posts', 'max')`); the one-arg call is a TypeScript error.
- **A custom `webpack` config breaks `next build` in 16** — Turbopack is the default and the build fails deliberately. Use `next build --webpack`, migrate, or `--turbopack` to ignore it. A plugin is often the hidden source of the `webpack` option.
- **`middleware.ts` is deprecated — rename to `proxy.ts`** (and the function to `proxy`). But `proxy` runs on `nodejs` only: code needing the `edge` runtime must keep the old `middleware` file.
- **Every parallel-route slot needs `default.tsx` in 16** — builds fail without it; add one that calls `notFound()` or returns `null`.
- **Reading runtime data in a layout blocks navigation** — `loading.tsx` sits below the layout, so `cookies()`/`headers()`/uncached fetches in `layout.tsx` have no loading fallback. Move them to `page.tsx` or wrap in `<Suspense>`.
- **Server Actions are public endpoints** — verify authentication and authorization inside every action; the form UI is not a security boundary.
- **`'use client'` pulls in everything the file imports** — keep the directive low in the tree to limit client JS; third-party components using hooks/DOM need a client wrapper file.
- **Props to client components must be serializable** — no functions (except Server Functions), class instances, or DOM nodes; pass promises instead and resolve with `use()`.
- **Only `NEXT_PUBLIC_*` env vars reach the client** — unprefixed vars become empty strings on the client; mark secrets with `server-only` and `taint` to catch leaks.
- **`route.ts` and `page.tsx` cannot share a segment** — `route` takes over all HTTP verbs for that URL.
- **Layouts don't re-render on client navigation** — they are cached; they cannot read `pathname`/`searchParams`. Use `template.tsx` for per-navigation remounts, `usePathname`/`useSearchParams` in client components for URL state.
- **Local image `src` with query strings requires `images.localPatterns[].search` in 16** — otherwise requests are blocked (anti-enumeration). Also: `minimumCacheTTL` is now 4h, `qualities` defaults to `[75]`, redirects capped at 3.
- **`next build` no longer lints and no longer prints `size`/`First Load JS`** — run ESLint/Biome yourself (`next lint` is gone); measure performance with Lighthouse/RUM.
- **`process.argv.includes('dev')` is false inside `next.config` during dev in 16** — the config loads once now; check `NODE_ENV` or `phase`.
- **`use cache` cannot sit directly in a Route Handler body** (Cache Components model) — extract to a helper function.
- **`Math.random()`/`Date.now()`/`crypto.randomUUID()` need explicit handling** with Cache Components — `await connection()` + `<Suspense>` for per-request values, or cache the value.
- **Route groups and private folders change nothing about URLs** — `(group)` is invisible, `_folder` is non-routable; don't "fix" them by adding paths.
- **`useSearchParams()` must be wrapped in `<Suspense>`** when used in a component that prerenders, or the build errors.
- **Sass tilde imports (`~pkg`) don't work in Turbopack** — drop the tilde or alias `~*` → `*`.
