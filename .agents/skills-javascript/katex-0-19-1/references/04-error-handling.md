# Error Handling and Security

From `docs/error.md` and `docs/security.md` (v0.19.1).

## ParseError

If KaTeX encounters an error (invalid or unsupported LaTeX) and `throwOnError` is not `false`, `katex.render` and `katex.renderToString` throw an exception of type `katex.ParseError` with properties:

```ts
class ParseError implements Error {
    name: "ParseError";
    position: number;   // position of the error in the input
    length: number;
    rawMessage: string; // message without source context
    message: string;    // includes some of the LaTeX source code
}
```

The message includes some of the LaTeX source code, so it **needs to be escaped** if you want to render it to HTML. Canonical pattern:

```js
try {
    var html = katex.renderToString(texString);
    // '<span class="katex">...</span>'
} catch (e) {
    if (e instanceof katex.ParseError) {
        // KaTeX can't parse the expression
        html = ("Error in LaTeX '" + texString + "': " + e.message)
            .replace(/&/g, "&amp;").replace(/</g, "&lt;").replace(/>/g, "&gt;");
    } else {
        throw e;  // other error
    }
}
```

In particular, convert `&`, `<`, `>` to `&amp;`, `&lt;`, `&gt;` before including **either** LaTeX source code **or** exception messages in your HTML/DOM. Failure to escape makes a `<script>` injection attack possible if your LaTeX source is untrusted.

Alternative: set `throwOnError: false` to use the built-in behavior of rendering the LaTeX source code with hover text stating the error (color from `errorColor`, default `#cc0000`).

## Security model

Any HTML generated by KaTeX *should* be safe from `<script>` or other code injection attacks. It is still a good idea to sanitize the HTML, though you will need a rather generous whitelist (including some of SVG and MathML) to support all of KaTeX.

Options giving finer control over security of untrusted inputs:

- `maxSize` — prevent large width/height visual affronts (`\rule{500em}{500em}` etc.). Default `Infinity`.
- `maxExpand` — prevent infinite macro loop attacks. Default `1000`.
- `trust` — gate commands that may load external resources or change HTML attributes and are thus not always safe (e.g. `\includegraphics`, `\href`, `\url`, `\htmlClass`, `\htmlId`, `\htmlStyle`, `\htmlData`). Default `false`.

Error messages thrown by KaTeX may contain unescaped LaTeX source code — see escaping rules above.

## Reporting a vulnerability

1. Report privately by opening a GitHub security advisory (`github.com/KaTeX/KaTeX/security`) or emailing katex-security@mit.edu.
2. The team evaluates the vulnerability and, if necessary, releases a fix and security advisory.
3. Do not disclose the vulnerability publicly until after a fix has been released.
