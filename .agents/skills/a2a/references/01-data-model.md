# A2A Data Model

The A2A protocol defines a canonical data model using Protocol Buffers. All protocol bindings must provide functionally equivalent representations.

## Task

The fundamental unit of work in A2A. Tasks are stateful and progress through a defined lifecycle.

```protobuf
message Task {
  string id = 1;                    // Server-generated UUID
  string context_id = 2;            // Groups related tasks/messages
  TaskStatus status = 3;            // Current lifecycle state
  repeated Artifact artifacts = 4;  // Task outputs
  repeated Message history = 5;     // Conversation turns
  google.protobuf.Struct metadata = 6;
}
```

### TaskState Enum

| State | Type | Description |
|---|---|---|
| `TASK_STATE_UNSPECIFIED` | Unknown | Indeterminate state |
| `TASK_STATE_SUBMITTED` | Active | Task acknowledged, not yet processing |
| `TASK_STATE_WORKING` | Active | Actively being processed |
| `TASK_STATE_COMPLETED` | Terminal | Finished successfully |
| `TASK_STATE_FAILED` | Terminal | Finished with an error |
| `TASK_STATE_CANCELED` | Terminal | Canceled before completion |
| `TASK_STATE_INPUT_REQUIRED` | Interrupted | Agent needs additional user input |
| `TASK_STATE_REJECTED` | Terminal | Agent decided not to perform the task |
| `TASK_STATE_AUTH_REQUIRED` | Interrupted | Authentication needed to proceed |

### TaskStatus

```protobuf
message TaskStatus {
  TaskState state = 1;
  Message message = 2;              // Status message from the agent
  google.protobuf.Timestamp timestamp = 3;  // ISO 8601 UTC
}
```

## Message

A single communication turn between client and server.

```protobuf
message Message {
  string message_id = 1;            // Creator-generated UUID
  string context_id = 2;            // Optional context grouping
  string task_id = 3;               // Optional task association
  Role role = 4;                    // ROLE_USER or ROLE_AGENT
  repeated Part parts = 5;          // Content containers
  google.protobuf.Struct metadata = 6;
  repeated string extensions = 7;   // Extension URIs used
  repeated string reference_task_ids = 8;  // Referenced tasks
}
```

### Role Enum

| Value | Description |
|---|---|
| `ROLE_USER` | Message from client to server |
| `ROLE_AGENT` | Message from server to client |

## Part

The smallest content unit within Messages and Artifacts. A Part contains **exactly one** of the following:

```protobuf
message Part {
  oneof content {
    string text = 1;                // Plain text content
    bytes raw = 2;                  // Binary data (base64 in JSON)
    string url = 3;                 // URI reference to external content
    google.protobuf.Value data = 4; // Structured JSON value
  }
  google.protobuf.Struct metadata = 5;
  string filename = 6;              // Optional file name
  string media_type = 7;            // MIME type (e.g., "image/png")
}
```

### Part usage patterns

- **Text messages:** `Part(text="Hello")` — for conversational content
- **File upload (inline):** `Part(raw=b64data, filename="doc.pdf", media_type="application/pdf")` — for small files
- **File reference:** `Part(url="https://storage.example.com/file.pdf", filename="doc.pdf", media_type="application/pdf")` — for large files
- **Structured data:** `Part(data={"key": "value"}, media_type="application/json")` — for machine-readable data

## Artifact

Tangible outputs generated by an agent during task processing.

```protobuf
message Artifact {
  string artifact_id = 1;           // Unique within a task
  string name = 2;                  // Human-readable name
  string description = 3;           // Optional description
  repeated Part parts = 4;          // Content (at least one part)
  google.protobuf.Struct metadata = 5;
  repeated string extensions = 6;
}
```

Artifacts are the deliverables of a task. Messages communicate; artifacts deliver results.

## Streaming Events

### TaskStatusUpdateEvent

Notifies the client of a task state change.

```protobuf
message TaskStatusUpdateEvent {
  string task_id = 1;
  string context_id = 2;
  TaskStatus status = 3;
  google.protobuf.Struct metadata = 4;
}
```

### TaskArtifactUpdateEvent

Delivers new or updated artifacts, supporting incremental streaming.

```protobuf
message TaskArtifactUpdateEvent {
  string task_id = 1;
  string context_id = 2;
  Artifact artifact = 3;
  bool append = 4;                  // Append to previous artifact with same ID
  bool last_chunk = 5;              // Final chunk of this artifact
  google.protobuf.Struct metadata = 6;
}
```

## Agent Discovery Objects

### AgentCard

The digital business card for an A2A server.

```protobuf
message AgentCard {
  string name = 1;                      // Human-readable name
  string description = 2;               // Purpose description
  repeated AgentInterface supported_interfaces = 3;  // Endpoints
  AgentProvider provider = 4;           // Service provider info
  string version = 5;                   // Agent version
  string documentation_url = 6;         // Optional docs URL
  AgentCapabilities capabilities = 7;   // Supported features
  map<string, SecurityScheme> security_schemes = 8;
  repeated SecurityRequirement security_requirements = 9;
  repeated string default_input_modes = 10;  // Media types
  repeated string default_output_modes = 11;
  repeated AgentSkill skills = 12;      // Agent's capabilities
  repeated AgentCardSignature signatures = 13;  // JWS signatures
  string icon_url = 14;                 // Optional icon
}
```

### AgentInterface

Declares a target URL, transport, and protocol version.

```protobuf
message AgentInterface {
  string url = 1;                       // HTTPS URL in production
  string protocol_binding = 2;          // JSONRPC, GRPC, HTTP+JSON, or URI
  string tenant = 3;                    // Optional routing identifier
  string protocol_version = 4;          // e.g., "1.0", "0.3"
}
```

### AgentCapabilities

Optional features supported by the agent.

```protobuf
message AgentCapabilities {
  bool streaming = 1;                   // SSE streaming support
  bool push_notifications = 2;          // Webhook push support
  repeated AgentExtension extensions = 3;  // Protocol extensions
  bool extended_agent_card = 4;         // Authenticated extended card
}
```

### AgentSkill

A distinct capability the agent can perform.

```protobuf
message AgentSkill {
  string id = 1;                        // Unique identifier
  string name = 2;                      // Human-readable name
  string description = 3;               // Detailed description
  repeated string tags = 4;             // Keywords for discovery
  repeated string examples = 5;         // Sample prompts
  repeated string input_modes = 6;      // Override default input modes
  repeated string output_modes = 7;     // Override default output modes
  repeated SecurityRequirement security_requirements = 8;
}
```

### AgentProvider

```protobuf
message AgentProvider {
  string url = 1;                       // Provider website URL
  string organization = 2;             // Organization name
}
```

## Push Notification Objects

### PushNotificationConfig

Webhook configuration for async task updates.

```protobuf
message TaskPushNotificationConfig {
  string tenant = 1;                    // Optional routing
  string id = 2;                        // Config UUID
  string task_id = 3;                   // Associated task
  string url = 4;                       // Webhook URL (HTTPS)
  string token = 5;                     // Client-side validation token
  AuthenticationInfo authentication = 6;  // Server-to-webhook auth
}
```

### AuthenticationInfo

```protobuf
message AuthenticationInfo {
  string scheme = 1;                    // HTTP auth scheme (Bearer, Basic, etc.)
  string credentials = 2;               // Credentials for the scheme
}
```

## Extensions

Agents declare extensions in their Agent Card. Extensions add functionality beyond the core protocol.

```protobuf
message AgentExtension {
  string uri = 1;                       // Unique URI identifier
  string description = 2;               // How this agent uses the extension
  bool required = 3;                    // Client must comply if true
  google.protobuf.Struct params = 4;    // Extension-specific parameters
}
```

Extensions are activated via the `A2A-Extensions` header (comma-separated URIs). Extension data lives in `metadata` maps keyed by the extension URI.

## AgentCardSignature

JWS signatures for Agent Card integrity verification (RFC 7515).

```protobuf
message AgentCardSignature {
  string protected = 1;                 // Base64url-encoded JWS header
  string signature = 2;                 // Base64url-encoded signature
  google.protobuf.Struct header = 3;    // Unprotected header values
}
```

## Security Objects

A2A supports multiple authentication schemes aligned with OpenAPI Specification:

- `APIKeySecurityScheme` — API key in header, query, or cookie
- `HTTPAuthSecurityScheme` — HTTP authentication (Basic, Bearer, etc.)
- `OAuth2SecurityScheme` — OAuth 2.0 with authorization code, client credentials, or device code flows
- `OpenIdConnectSecurityScheme` — OpenID Connect discovery
- `MutualTlsSecurityScheme` — Mutual TLS authentication

Each scheme is declared in `AgentCard.security_schemes` and referenced in `AgentCard.security_requirements`.
