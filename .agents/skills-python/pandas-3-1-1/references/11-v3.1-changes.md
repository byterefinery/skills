# v3.1 Changes and Migration Reference

Breaking changes, new features, deprecations, and migration guidance for pandas 3.1.x (3.1.0, 3.1.1).

## New Features in v3.1.0

### `DataFrame.select`

Select columns by label, `pd.col()` expression, or callable kwargs. Later kwargs may refer to columns computed earlier in the same call (like `assign`).

```python
from pandas import col
df.select("first_name", col("age"), age_months=col("age") * 12)
```

### Boolean-Mask Filtering in `filter`

`DataFrame.filter` / `Series.filter` accept `cond=` — a boolean mask, a callable returning a mask, or a `pd.col()` expression (callable and expression also work positionally). Missing values in the mask are treated as `False` by default; `na=True` keeps entries, `na="raise"` raises.

```python
df.filter(cond=df["a"] > 1)
df.filter(col("a") > 1)
df.filter(lambda d: d["b"] < 6)
```

### Faster Parallel `read_csv`

The C engine is 2–3× faster than 3.0 (tokenizing, type inference, int/float/string/datetime conversion). Large files (local, uncompressed, ≥ 5 MB, no whole-file options) read in parallel by default; result is identical to a serial read. `mode.max_threads` controls threads (default: available CPUs, capped at 6; set to 1 for serial).

## Notable Bug Fixes (behavior changes)

### `Timedelta.total_seconds` Includes Nanoseconds

Scalar `Timedelta.total_seconds()` previously dropped the sub-microsecond nanosecond residual (mirroring stdlib `datetime.timedelta`); it now includes it, matching the vectorized `.dt.total_seconds`.

### `read_csv` with `dtype="category"` Infers Numeric/Boolean Categories

All engines (c, python, pyarrow) now infer numeric and boolean categories. Identifier-like columns (zero-padded account numbers, zip codes) get integer categories, dropping leading zeros. To keep string categories: read as `str` and `.astype("category")`.

### String Regex Methods Align with Python `re`

PyArrow-backed string regex behavior from 3.0 was corrected: `\w`, `\d`, `\s`, `\b` match unicode again; `$` anchoring fixed around newlines; `\u`/`\U`/`\N{}` escapes work again. (3.1.1 additionally fixed `\s` not matching `\x0b`/`\x1c` whitespace in all-ASCII data.)

### `Timestamp` Component Handling

Mixing a value-to-convert with keyword date components now raises `ValueError`; positional `tzinfo` (8th arg) is now attached instead of dropped.

## Backwards Incompatible API Changes

### Datetime/Timedelta Resolution for Numeric Input

Numeric input to `to_datetime`, `to_timedelta`, `Timestamp`, `Timedelta` now defaults to **microsecond** resolution (ns if the input precision requires it), not the input `unit`'s resolution. Compare 2.x: nanoseconds. Use `.as_unit()` to convert afterwards.

### Other API Changes (selection)

- `Index.values` / `Index.array` return **read-only** arrays for all dtypes
- DataFrame arithmetic/comparison with an extension-dtype Series along columns keeps the extension dtype (`Int64` not `int64`, `boolean` not `bool`); declined operations raise (category ordering → `TypeError`)
- `Timedelta`/`to_timedelta` raise on strings with trailing characters (e.g. `"3:25:00 PM"` — previously parsed as 3 hours)
- Zero-UTC-offset non-ISO strings return stdlib `datetime.timezone.utc` (repr `tz='UTC'`)
- `infer_freq` on quarter-start data reports first-calendar-quarter anchor (`QS-JAN` not `QS-OCT`)
- `read_csv`/`read_table` raise `ValueError` when `delimiter=None` is passed with `sep`
- `assert_frame_equal(check_freq=True)` also checks freq of DatetimeIndex/TimedeltaIndex *columns*
- `GroupBy.sum`/`mean` on floats with sorted keys may differ in last digits (faster summation, no Kahan compensation)
- `GroupBy.sum`/`prod` on Arrow decimal columns return max-precision decimals
- `select_dtypes` raises on non-dtype classes, exact-match dtype instances, `"datetime64[ns]"` selects ns only (see 02-data-types)
- `DataFrame.sum/prod/min/max/mean` with `axis=1` on mixed bool+numeric now returns NumPy dtype (may overflow/lose precision)
- `to_hdf` no longer writes `pandas_version`; `format="table"` files are incompatible across the 3.0/3.1 boundary
- `HDFStore.where=` ordering comparisons on unordered categoricals raise `TypeError`
- `Index.join` left/right on mixed dtypes keeps the source index dtype (affects `align`, `join`, `merge`, `str.cat`)
- `Series.shift` with `suffix=` + integer `periods` raises `ValueError`
- numba `nopython` no longer forwarded via `engine_kwargs`
- `freq`/`freqstr` attributes removed from `DatetimeArray`/`TimedeltaArray` (use `Series.dt.freq` or wrap in an Index)
- `isocalendar` year column is now `int32` (was `uint32`)
- **numexpr 2.14.1 is bypassed** — that release intermittently returned incorrect results; pandas falls back to NumPy with a one-time warning and raises `ImportError` for explicit `engine="numexpr"`. Install ≥ 2.14.2 to restore acceleration.

## Deprecations (v3.1.0)

### `inplace` Keyword (PDEP-8)

Deprecated for methods that don't actually work inplace: `drop`, `rename`, `rename_axis`, `reset_index`, `set_index`, `dropna`, `drop_duplicates`, `sort_values`, `sort_index`, `eval`, `query`. Reassign the result (`df = df.reset_index()`). Methods that can update underlying values (`fillna`, `replace`) keep the keyword.

### Lossy `.values`

`.values` for `DatetimeTZDtype`, `PeriodDtype`, `IntervalDtype` emits `Pandas4Warning`; will return the ExtensionArray in 4.0. Use `.array` or `.to_numpy()` (see 10-copy-on-write).

### Inferred Frequencies Return Offsets

`infer_freq`, `DatetimeIndex.inferred_freq`, `TimedeltaIndex.inferred_freq`, `Series.dt.freq` will return a `BaseOffset` instead of a string. Opt in with `future.infer_freq_returns_offset=True`; use `.freqstr` on the result to get the string.

### Other Deprecations (selection)

- `Timestamp.dayofweek` / `dayofyear` / `daysinmonth` → `day_of_week` / `day_of_year` / `days_in_month` (also on `Period`, indexes, `.dt`)
- `PeriodIndex`/`PeriodArray` inferring freq from datetime64 Series — pass `freq` explicitly
- `pd.set_eng_float_format` → `display.precision` / `display.float_format` option
- `GroupBy.agg`/`Resampler.agg` unpacking scalars from length-1 Series/array returns
- `select_dtypes` matching `str` dtype when `object` is in `exclude` — pass `"str"` explicitly
- `ExcelFile.parse` → `read_excel`
- `Series.fillna` with an incompatible value requiring dtype casting — cast first
- `PeriodIndex.is_full` — use `index.empty or len(index.unique()) == len(period_range(...))`
- `engine="fastparquet"`/`"auto"` in Parquet — fastparquet is retired; use pyarrow
- `pandas.core.accessor.CachedAccessor` → `Accessor`
- Operations between pandas objects and non-standard list-likes (`tuple`, `range`) — cast explicitly
- Dtype promotion when reindexing with an incompatible `fill_value` — cast first
- `DataFrame` from list of sequences with mismatched lengths (silent NaN padding)
- Expanding MultiIndex objects with non-full-length tuple keys — use full tuples or `to_flat_index()`
- Grouping by an index level name matching multiple MultiIndex levels — use level number
- Implicit `datetime.date` → `Timestamp` conversion when indexing/joining a DatetimeIndex — use `to_datetime`
- Indexing `GroupBy.nth` with `[]` — call `gb.nth([0, 1])`
- Parsing quarterly strings (`"2014Q2"`) in Timestamp/to_datetime/partial indexing — use `Period`
- `None` inside `select_dtypes` include/exclude list-like — pass `"float64"`
- `dict` to `DataFrame.from_records` / non-dict to `from_dict` — use the constructor
- Integer/float values to `to_datetime` with `format=` — cast to strings first
- Unnecessary `*args`/`**kwargs` to GroupBy `cum*`/`skew`/`take`
- Default xlsx engine changing `openpyxl` → `calamine` when python-calamine is installed — pass `engine` explicitly
- Setting values with `.at`/`.iat` at a nonexistent key (expansion) — use `.loc`
- Silent dtype changes in setitem-with-expansion
- `Period.strftime` `%n` → `%N` for nanoseconds
- Offset `.name` → `.rule_code`
- `Groupby` → `GroupBy` spellings in `pandas.api.typing`
- `read_json` `convert_dates`/`keep_default_dates` — use `dtype=False` or parse after
- `DatetimeIndex` `dayfirst`/`yearfirst`/`ambiguous` keywords — use `to_datetime`/`tz_localize`
- `to_hdf`/`HDFStore.put/append` `dropna` — drop rows before writing
- `read_csv`/`read_table`/`read_fwf` `float_precision` — all modes share one converter now
- `future.infer_string` option — str inference is permanent
- `Series.describe` `include`/`exclude` — had no effect on a Series
- `DataFrame.join` `lsuffix`/`rsuffix` → `suffixes`
- `mode.chained_assignment` option — chained assignment emits `ChainedAssignmentError` (Warning subclass); filter with `warnings.filterwarnings`
- `SparseArray.sparse_index` parameter — use `SparseArray.from_indices`
- `.weekday` property on DatetimeIndex/DatetimeArray/PeriodIndex/PeriodArray/Period — use `day_of_week`
- `read_excel` `xlrd`/`pyxlsb` engines — use `engine="calamine"`
- `read_sas` default `encoding` changing from `None` to `"infer"` — pass explicitly
- `assert_index_equal` `exact` default changing to `True`
- `HDFStore.put` `track_times` default changing to `False`
- `datetime.date` → `datetime64` inference in comparisons/`Index.equals` with DatetimeIndex
- `assert_frame_equal` `by_blocks` keyword
- Non-NumPy/EA array-like handling in indexing/setitem — convert with `np.asarray`/`pd.array`
- `to_json` `date_format="epoch"` warning also for index/column labels
- Non-boolean `numeric_only` for DataFrame/Series reductions — will raise
- Integers to `Period`/`PeriodIndex`/`period_range` (future: ordinals) — pass strings or `ordinal=`
- `convert_dtypes` `infer_objects`/`convert_*` keywords
- `isinstance(obj, DateOffset)` for non-DateOffset types — use `pd.offsets.BaseOffset`
- Tuple keys in `Resampler.__getitem__`/`SelectionMixin` selection — use a list

## Packaging Changes (v3.1.0)

- **NumPy ≥ 2 required** — `numpy>=2.0.2` (`>=2.3.3` on Python 3.14); NumPy 1.x support dropped
- `python-dateutil>=2.9.0` (3.1.1 fixed dateutil 3.0 tz compatibility)
- Python ≥ 3.11
- Optional minimums: pyarrow 16.0.0, bottleneck 1.5.0, numexpr 2.11.0, lxml 6.0.0, fsspec/gcsfs 2025.7.0, beautifulsoup4 4.13.4, matplotlib 3.10.5, pyiceberg 0.9.1, etc.

## v3.1.1 Patch (November 4, 2026)

Fixed regressions:
- `astype`/`convert_dtypes` with `dtype_backend="pyarrow"` overwriting missing datetime values with the Unix epoch
- `Series.map` with datetime-like values returning a read-only Series
- IO readers/writers treating path objects with `read`/`write` methods (e.g. pytest's `py.path.local`) as open file handles

Bug fixes:
- python-dateutil 3.0 compatibility for dateutil timezones (`"dateutil/US/Pacific"`)
- `Series.ffill`/`bfill` (and DataFrame) on PyArrow-backed columns without missing values shared data with the original, violating CoW
- String regex on PyArrow-backed strings: `\s` not matching `\x0b`/`\x1c` whitespace in all-ASCII data

Build: fixed build error on architectures not supported by `xsimd` (e.g. s390x).

## Migration Checklist (3.0.x → 3.1)

1. **Upgrade NumPy to ≥ 2** before installing pandas 3.1
2. **Remove `inplace=True`** from the listed methods; reassign the result
3. **Replace lossy `.values`** with `.array`/`.to_numpy()` for tz-aware/period/interval data
4. **Check resolution assumptions** — numeric datetime/timedelta construction now yields `us`; use `.as_unit()`
5. **Audit `read_csv` performance** — large reads are parallel; set `mode.max_threads` if the app parallelizes already
6. **Fix chained assignment** — expect `ChainedAssignmentError` warnings; use `.loc`
7. **Switch `mode.chained_assignment`** to `warnings.filterwarnings(..., category=ChainedAssignmentError)`
8. **Replace deprecated day-of attrs** — `dayofweek` → `day_of_week`, etc.
9. **Replace `lsuffix`/`rsuffix`** with `suffixes` in `df.join`
10. **Drop fastparquet** — pin `engine="pyarrow"`
11. **Fix `select_dtypes` calls** — non-dtype classes and partial dtype specs now raise
12. **Test `read_csv(dtype="category")`** — numeric/boolean categories inferred (leading zeros dropped)
13. **Install numexpr ≥ 2.14.2** if relying on numexpr acceleration
14. **Pin python-calamine/engine** if the xlsx default-engine warning matters

## Gotchas

- **`ChainedAssignmentError` is a `Warning`, not an `Exception`** — code catching it as an exception will miss it; filter with `warnings.filterwarnings`.
- **The `inplace` deprecation is selective** — `fillna(inplace=True)` and `replace(inplace=True)` are fine; only the listed non-inplace methods warn.
- **Parallel `read_csv` only applies to local, uncompressed files ≥ 5 MB** with no whole-file-parsing options; remote, compressed, or option-heavy reads stay serial.
- **`select_dtypes` exact-match for instances is a silent behavior change** — `include=np.dtype("int64")` no longer selects `Int64`/Arrow int64 columns.
- **HDF5 `format="table"` files do not cross the 3.0/3.1 boundary** — re-export if both sides must read them.
- **numexpr 2.14.1 data loss is silent in 3.1** — pandas falls back to NumPy with only a first-time warning; upgrade numexpr rather than suppressing the warning.
