# Type System

SQLAlchemy 2.1.9. Source: `core/type_basics.html` (published 2.1.9 docs), `orm/quickstart.rst` at tag `rel_2_1_9`.

## Built-in Types

```python
from sqlalchemy import (
    Integer, BigInteger, SmallInteger, Numeric, Float,
    String, Text, CHAR, VARCHAR, Boolean,
    Date, DateTime, Time, Interval,
    LargeBinary, JSON, Uuid, Enum, PickleType,
)

# Numeric
Column("id", Integer)                 # INTEGER
Column("big", BigInteger)             # BIGINT
Column("price", Numeric(10, 2))       # NUMERIC(10, 2)
Column("ratio", Float)                # FLOAT

# String
Column("name", String(100))           # VARCHAR(100)
Column("code", CHAR(3))               # CHAR(3)
Column("bio", Text)                   # unlimited length

# Boolean / dates / binary
Column("active", Boolean)
Column("born", Date)
Column("created", DateTime)
Column("data", LargeBinary)

# JSON — works with Python dicts/lists
Column("meta", JSON)

# UUID
Column("id", Uuid, primary_key=True)  # default=uuid.uuid4 common

# Enum — from Python enum or inline strings
Column("status", Enum(Status))         # Status is a Python enum class
```

- `Numeric(precision, scale)` for exact decimals (maps to `decimal.Decimal` in Python).
- `Uuid` handles `uuid.UUID` values; dialect-specific UUID variants exist under `sqlalchemy.dialects.*`.
- `Interval` is PostgreSQL-flavored; other dialects store differently.

## Mapped[] Type Coercion

The annotation determines the SQL type (see [04-declarative-orm](04-declarative-orm.md)). Overrides: `mapped_column(String(200))`, `mapped_column(JSON)`, etc. The default Python type → SQL type association can be remapped via the declarative type-annotation map; 2.1 adds the `resolve_type_annotation` registry event for programmatic interception (e.g. PEP 695 type aliases).

## TypeDecorator — Custom Types

Wrap an existing type with Python→DB / DB→Python processing:

```python
from sqlalchemy import TypeDecorator, String
import json

class JSONString(TypeDecorator):
    impl = String
    cache_ok = True   # required for statement caching unless the type is stateful

    def process_bind_param(self, value, dialect):
        return json.dumps(value) if value is not None else None

    def process_result_value(self, value, dialect):
        return json.loads(value) if value is not None else None
```

- `process_bind_param(value, dialect)` — Python → DB (before INSERT/UPDATE).
- `process_result_value(value, dialect)` — DB → Python (after SELECT).
- `cache_ok = True` enables SQL statement caching; omit only when the instance holds state that affects SQL.
- Compare semantics: `__eq__`/comparator methods can be overridden for expression-level behavior.

## Dialect-Specific Types

Import from `sqlalchemy.dialects.<backend>` for backend-specific types:

- **PostgreSQL** (`sqlalchemy.dialects.postgresql`): `JSONB`, `ARRAY`, `INET`, `CIDR`, `MACADDR`, `HSTORE`, `TSVECTOR`, ranges (`INT4RANGE`, `DATERANGE`, `TSTZRANGE`, …), `UUID`.
- **MySQL** (`sqlalchemy.dialects.mysql`): `ENUM`, `SET`, `YEAR`, `TINYINT`/`MEDIUMINT`/`BIGINT`, `LONGBLOB`, spatial `POINT`/`GEOMETRY`.
- **SQLite** has a limited type system — most types map to INTEGER/REAL/TEXT/BLOB affinity.
- **MSSQL** (`sqlalchemy.dialects.mssql`): `DATETIME2`, `UNIQUEIDENTIFIER`, `MONEY`.

## Type Operators (expression-level)

Types define how Python operators translate to SQL:

```python
User.name + User.last_name      # concatenation (|| in PG)
User.name.like("alice%")        # LIKE
User.name.ilike("ALICE%")       # case-insensitive (dialect-supported)
User.name.contains("alice")     # LIKE '%alice%'
User.name.startswith("a") / .endswith("z")
User.id.in_([1, 2, 3])          # IN
User.email.is_(None)            # IS NULL
User.age.between(18, 65)        # BETWEEN
```

Since 2.1, types validate operator usage via `operator_classes` (e.g. wrong operator/datatype combinations surface earlier).

## Nullability and Defaults

- Column nullability: `nullable=True/False` (Core) or `Optional[...]` (ORM annotation).
- Python-side default: `Column.default` / `mapped_column(default=...)` (or `insert_default` for INSERT-only).
- SQL-side default: `server_default` (string, `FetchedValue`, or `DefaultClause`) — value generated by the database.
- `onupdate` — Python-side value applied on UPDATE.
