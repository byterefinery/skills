# Authentication

## Token model

A client is authenticated as long as it sends a valid `Authorization: <token>` header (no `Bearer` prefix). The Web APIs are **fully stateless** — no sessions, tokens are not stored in the database (JWT, HS256), and there is **no logout endpoint**: "logout" means discarding the token locally (`pb.authStore.clear()`).

Tokens are generated by the auth collection Web APIs or programmatically (Go/JS). Each auth collection configures its own enabled methods, token duration, and token secret.

**Superusers** (`_superusers`) behave like regular auth records with two caveats: OAuth2 is not supported, and they bypass all collection API rules.

## Password

Enable *Identity/Password* in the collection options. Default identity field is `email`; any other field works if it has a UNIQUE index (e.g. `username`).

```js
const authData = await pb.collection('users').authWithPassword('test@example.com', '1234567890');
console.log(pb.authStore.isValid, pb.authStore.token, pb.authStore.record.id);
pb.authStore.clear(); // logout
```

## OTP (one-time email code)

Enable *One-time password (OTP)*. Flow: `requestOTP(email)` → email with code (template supports `{url}`/`{otp}`-style placeholders — adjust from collection options) → `authWithOTP(otpId, code)`.

- `requestOTP` returns an `otpId` even for unknown emails (rudimentary enumeration protection; nothing is sent).
- On success the user email is auto-marked verified.
- Weaker standalone (short numeric codes, guessable) — combine with another method + MFA for security-critical apps.

## OAuth2

Configure providers (Google, GitHub, Microsoft, GitLab, Apple, …) in the collection *Options → OAuth2*: Client Id, Client Secret, redirect URL, etc. PKCE is used.

### Modern flow (js-sdk, no custom redirects)

`authWithOAuth2({ provider })` opens a popup with the provider page and round-trips the code over a **one-off realtime subscription** — no page reload, no custom redirect page:

```js
// register https://yourdomain.com/api/oauth2-redirect in the provider dashboard
const authData = await pb.collection('users').authWithOAuth2({
    provider: 'google',
    // scopes: [...], createData: { name: '...' }, urlCallback: (url) => {...}
});
```

Safari may block the default popup when `window.open` is called inside an `async` click handler — either don't mark the handler async, or open the window yourself and pass it via `urlCallback`.

### Classic flow (links page + redirect page)

1. **Links page** — lists providers via `listAuthMethods()`, each link = `provider.authURL + redirectURL`; store the provider data (state, codeVerifier) on click.
2. **Redirect page** (registered URL, e.g. `http://127.0.0.1:8090/redirect.html` served from `pb_public/`) — after provider redirect: verify `state` matches the stored one, then:

```js
pb.collection('users').authWithOAuth2Code(
    provider.name,           // e.g. 'google'
    params.get('code'),      // from ?code=
    provider.codeVerifier,   // from stored provider data
    redirectURL,             // the same URL used in the provider config
    { emailVisibility: false } // optional create data for sign-up
).then(authData => { ... }).catch(err => { ... });
```

Full HTML/JS templates for both pages are in the official docs (authentication page, "Authenticate with OAuth2").

## Multi-factor authentication

Enable *MFA* (duration configurable). The user must authenticate with **2 different** methods (order irrelevant):

1. Method A succeeds → **401** with body `{ "mfaId": "..." }` (MFA session stored in `_mfas` system collection).
2. Method B is called as usual, **adding `mfaId`** as body or query parameter → regular auth response (token + record).

```js
try {
    await pb.collection('users').authWithPassword('test@example.com', '1234567890');
} catch (err) {
    const mfaId = err.response?.mfaId;
    if (!mfaId) throw err;
    const result = await pb.collection('users').requestOTP('test@example.com');
    await pb.collection('users').authWithOTP(result.otpId, 'EMAIL_CODE', { 'mfaId': mfaId });
}
```

## Impersonation

Superusers can authenticate as any record: `POST /api/collections/{idOrName}/impersonate/{recordId}` with optional `duration` (seconds). The generated token is **not renewable**. The SDK returns a standalone client with the token kept in memory:

```js
await pb.collection('_superusers').authWithPassword('admin@example.com', 'pass');
const client = await pb.collection('users').impersonate('USER_RECORD_ID', 3600);
const items = await client.collection('example').getFullList();
```

## API keys

PocketBase has no traditional API keys — use a generated non-renewable `_superusers` impersonate token (Dashboard → Collections → `_superusers` → record → Impersonate, or the API above) for internal **server-to-server** communication. To invalidate issued tokens, change the superuser's password (or the shared `_superusers` auth token secret for all).

## Token verification

There is no dedicated verify endpoint — call `authRefresh()` (or `pb.collection('users').authRefresh()`): a valid token returns a new token with refreshed `exp` and latest user data; otherwise an error. Refreshing does NOT invalidate previously issued tokens. Verification cost ≈ `getOne` (HS256 JWT).
